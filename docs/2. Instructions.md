# Instructions

## Building the Semantic Retriever — The Transformer Backbone of a RAG System

### Tasks Overview

You’ll complete the following high-level tasks, in this order:

#### 1. Generate Embeddings from a Transformer Model

In `transformer_retriever.py`, complete the methods to:

- Load a pretrained transformer model (e.g., from Hugging Face)
- Encode both the document corpus and incoming queries into dense vectors

This step transforms raw text into a format that lets us measure **semantic similarity**.

#### 2. Implement Semantic Retrieval Using Cosine Similarity

Also in `transformer_retriever.py`, implement the retrieval method that:

- Compares query embeddings with document embeddings using cosine similarity
- Returns the top-k most similar documents for each query

This method allows the system to “understand” which documents are meaningfully related to a question.

#### 3. Evaluate the Retriever with Recall@k, Precision@k, and MRR

In `evaluator.py`, complete the evaluation method that:

- Compares the retriever’s top-k results against a list of ground truth relevant documents
- Compute **Recall@k**, **Precision@k**, and **Mean Reciprocal Rank (MRR)** as a metric of retrieval quality

This step helps assess how well the retriever is performing, and lets you compare retrievers fairly on the same metrics.

#### 4. Build the Keyword-Based Baseline with BM25

In `bm25_retriever.py`, complete the methods to:

- Tokenize and preprocess the document corpus (lowercase and split into terms)
- Build a BM25 keyword index and score documents against each query
- Return the top-k highest-scoring documents per query

This gives you a traditional keyword-matching baseline, the starting point in the evolution of search.

#### 5. Build the Static-Embedding Baseline with Word2Vec

- In `word2vec_retriever.py`, complete the methods to:
- Preprocess the corpus and train a Word2Vec model on it
- Convert documents and queries to vectors by averaging their word embeddings
- Retrieve the top-k most similar documents using cosine similarity
- Run the hyperparameter optimization routine to find the best-performing configuration

This captures word-level meaning beyond exact keywords, the bridge between keyword search and transformers.

#### 6. Compare All Three Retrievers and Run the Demo

In unified_retrieval_comparison.ipynb, bring the retrievers together:

- Run BM25, Word2Vec, and the Transformer retriever on the same queries
- Evaluate each with your metrics and compare the results side by side
- Confirm that all three retrievers work together in the Streamlit demo app (streamlit/app.py)

This is where the project comes together: you can see, side by side, how retrieval quality evolves from keywords to semantic understanding.

#### 7. Visualize the Embedding Space

In `unified_retrieval_comparison.ipynb`, use a dimensionality reduction technique such as PCA or t-SNE to:

- Project high-dimensional embeddings into 2D
- Create a scatter plot to visualize semantic relationships

Include a short explanation in a markdown cell about what the plot shows (e.g., clustering of similar queries).

#### 8. Explain the Retriever’s Role in a RAG System

Finally, add a short written explanation (in the notebook or README) describing:

- How your retriever fits into a Retrieval-Augmented Generation (RAG) architecture
- How it works with a generator model (e.g., a large language model)
- How this architecture powers real-world tools like ChatGPT, Copilot, or Perplexity
- What your comparison reveals about the evolution from keyword search (BM25) to static embeddings (Word2Vec) to transformer-based semantic search
