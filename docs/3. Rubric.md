# Rubric

Use this project rubric to understand and assess the project criteria.

## Embedding Generation

### Criteria

Student code includes a function for encoding documents and queries using a pretrained Hugging Face transformer

### Submission Requirements

- The function is implemented in transformer_retriever.py
- Uses a model from sentence-transformers to encode both the corpus and the queries
- Embeddings are returned as numpy arrays or tensors with shape (n_samples, embedding_dim)
- All TODOs in regards to encoding documents and queries in build_index() **and** retrieve() functions are completed

## Semantic Retrieval Pipeline

### Criteria

Student code includes a method that performs top-k document retrieval using cosine similarity

### Submission Requirements

- retrieve() method is implemented in transformer_retriever.py
- Cosine similarity is computed between query and document embeddings
- The top-k most similar documents are returned per query
- Retrieval results are returned as dictionary with query indices as keys and document ID lists as values → {0: [doc_id1, doc_id2, ...], 1: [...]}

## Evaluation and Metrics

### Criteria

Student code implements standard IR metrics (Recall@k, Precision@k, MRR) evaluation in evaluator.py and logs metric results

### Submission Requirements

- `recall_at_k()`, `precision_at_k()`, and `mrr()` functions in `evaluator.py` are implemented from scratch
- Evaluation uses a dictionary of ground truth relevant documents
- Final metric results are printed or logged in the notebook
- All TODOs in `evaluator.py` are completed

## Complete Retrieval System Implementation

### Criteria

Student implements BM25 and Word2Vec retrievers to complete the comparison pipeline

### Submission Requirements

- BM25Retriever class properly tokenizes text and builds keyword-based index
- Word2VecRetriever trains embeddings, converts documents to vectors, and includes hyperparameter optimization
- All three retrievers (BM25, Word2Vec, Transformer) work together in the Streamlit demo application

## System-Level Explanation of RAG Workflow

### Criteria

Notebook or README includes a written explanation of how the retriever supports a RAG pipeline

### Submission Requirements

- A markdown cell or README paragraph explains that the retriever selects relevant documents for the generator
- The explanation mentions retrieval followed by generation
- At least one real-world system (e.g., Perplexity, Copilot, ChatGPT) is mentioned as an example
- Student demonstrates understanding of the evolution from keyword search (BM25) to semantic search (transformers)
- Analysis includes performance comparison between the three retrieval methods
